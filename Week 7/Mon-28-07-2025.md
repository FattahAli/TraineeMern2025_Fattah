# Web Storages 

- Two main types: `localStorage` and `sessionStorage`
- localStorage persists even after the browser is closed
- sessionStorage is cleared when the page session ends
- Both store data in key-value pairs and are synchronous
- Not secure for storing sensitive information like tokens

# JWT Tokens

- JSON Web Tokens used for stateless authentication
- Contains Header, Payload, and Signature
- Sent in HTTP headers (usually Authorization: Bearer <token>)
- Can be verified without querying the database
- Avoid storing JWTs in localStorage due to XSS risks

# Session vs JWT Tokens

- **Session**: Stored on server; uses cookies with session IDs
- **JWT**: Token is stored on client; server doesn’t store state
- Sessions can be invalidated easily from server
- JWTs scale better with microservices but harder to revoke
- Sessions more secure (stored on server), JWTs more scalable

# Session Authentication in React

- Use secure cookies for session ID storage
- React app sends requests with `credentials: 'include'`
- Backend checks session ID and responds accordingly
- Best with CSRF protection and HTTPS enabled
- Use HttpOnly cookies to prevent XSS attacks

# Why Not to Use Local Storage

- Vulnerable to XSS attacks
- Cannot be set as HttpOnly or Secure
- Accessible via JavaScript from any script on the page
- Not suitable for storing auth tokens or sensitive data
- Prefer cookies (with HttpOnly, Secure, SameSite)
